## 1. Signal-killed children are not file properties

- New error code **`RESOURCE_EXHAUSTED`**, retryable, in the zod enum, the Pydantic enum, `errors.py` and a fixture
  (`task-status.resource-exhausted.valid.json`). Contract parity tests compare both enums.
- `media_io.signal_failure_code(outcome, returncode)`: a negative return code **with outcome `EXITED`** is a signal the
  runner did not send (the runner signals only after it has decided timeout, cancel or output limit, and those outcomes
  keep their own mapping). **SIGXCPU maps to `TIMEOUT`** (the CPU rlimit is derived from the child's wall-clock timeout, so
  it is the same condition); every other signal (SIGKILL from the cgroup OOM killer, SIGSEGV, SIGABRT, SIGBUS, ...) maps to
  `RESOURCE_EXHAUSTED`. `raise_for_outcome` applies it to every ffprobe and ffmpeg run (probe, edge packets, trial decode,
  packet scan, loudness), and the streamed decoder applies it to both decode passes and does not emit a trailing partial
  block after a kill.
- The best-effort edge-packet scan used to swallow every failure but `TIMEOUT`; it now re-raises `RESOURCE_EXHAUSTED` too.
- Trial decode: a signal death is a failure whatever it had decoded; a normal non-zero exit with output is counted as one
  decoder error (`trial_decode_errors`).
- Container test: a real `SIGKILL` of the FFmpeg child on the first chunk of the canonical pass and of the native pass:
  `RESOURCE_EXHAUSTED`, no `manifest.json`, no published file, no temp directory, no surviving child, and the next run
  recomputes (nothing reused). The test asserts that a child was actually killed (`SIGKILLED_*_PASS_CHILDREN=1`).
- The older test `test_a_failing_ffprobe_maps_to_a_code[--11-CORRUPT_MEDIA]` pinned the bug (SIGSEGV -> `CORRUPT_MEDIA`); its
  expectation is now `RESOURCE_EXHAUSTED`. This is the one existing expectation that changed on purpose.

**Open point for the reviewer (not changed).** Non-signal, non-zero exits (for example ffmpeg exit status 1 after some
output) still yield `decodeClass: partial`, as before. The fix list said a native or canonical pass whose `clean_exit` is
false must fail, but the existing unit test `test_a_partial_decode_covers_only_the_decoded_audio` deliberately models a
canonical pass that exits non-zero after decoding half the file and requires a published `partial` result. Making that a
failure would reverse an existing test, so only the **signal** case (the data-integrity bug) is a failure. Decide whether
a non-zero normal exit should also fail; the change is one check in `preprocess.py` plus that test.

## 2. Overall task deadline (ADR-0010)

- `TaskDeadline` in `domain/tasks.py`, started when the task begins running: `base_ms + audio_duration_ms * permille /
  1000`. Settings **`AUDIO_SERVICE_TASK_DEADLINE_BASE_MS`** (default 120000) and
  **`AUDIO_SERVICE_TASK_DEADLINE_PER_AUDIO_MS_PERMILLE`** (default 500): exactly the existing interim per-child formula
  `120 s + 0.5 x duration`, **interim, OD-10 / D-2B-20 Open, not approved**; no new number. Until the duration is known the
  configured duration ceiling is used (`AUDIO_SERVICE_MAX_DURATION_MS`, default 4 h: 2 h 2 min); `preprocess` tightens it to
  the larger of the header and packet-scan durations; `probe` uses the base alone (it reads a bounded prefix and decodes
  30 s). A deadline is only ever shortened.
- The `CancellationToken` the runner and decoder already poll reports `cancelled` when the deadline passes, so the
  process group is killed (SIGTERM, SIGKILL after 2 s), the `OutputSession` removes the temp directory, and the executor
  maps the stop to **`failed` / `TIMEOUT` / retryable** (an explicit cancel still gives `cancelled`).
- The task status gains optional **`deadlineAt`** (integer epoch milliseconds, `null` or absent while queued) in the zod
  schema, the Pydantic mirror and fixtures. Node can use it as a backstop. It can move earlier once the duration is known
  (never later).
- Test with the real `SandboxRunner`: a 30 s `sleep` standing in for FFmpeg is cut at a 0.5 s deadline and no temp
  directory remains.

Not measured: a whole real preprocess of a long recording against the default deadline. With the defaults the deadline
(120 s + 0.5 x duration) is about the size of one per-child timeout, so a task whose several passes together take longer
than half its audio duration would now time out where each pass alone would not. The measured WS4 passes run far faster
than real time, but the figure needs the benchmark of WS9 and a decision on OD-10.

## 3. Landlock `required` means enforced

- Under `required`, `SandboxRunner.run` raises `SandboxError` unless `verify_enforcement()` has passed (previously only
  "no ruleset available"). The self-test itself runs through the internal `_run`.
- Self-test: (a) canary read denied (all ABIs); (b) ABI >= 4: a confined `python -I -S` child gets `PermissionError` on a
  TCP connect to a listening local port; (c) ABI >= 6: `PermissionError` when signalling the parent (SIGURG, harmless if it
  were delivered) and when connecting to a parent-owned **abstract UNIX socket**. A control that cannot be checked (no
  interpreter a child may execute under `/usr`) counts as not enforced. `enforced` is true only if every control the kernel
  offers was observed denying; `scoped` (new, `landlock.scoped` in `/v1/capabilities`, optional in zod, default false in
  Pydantic) is true only if (c) was observed.
- ABI >= 6 rulesets set `LANDLOCK_SCOPE_SIGNAL | LANDLOCK_SCOPE_ABSTRACT_UNIX_SOCKET`; the ruleset attribute struct size
  follows the ABI (8, 16 or 24 bytes).
- `prctl(PR_SET_DUMPABLE, 0)` in the parent at startup (`landlock.disable_dumping`, called first in the lifespan). Container
  test: an **unconfined** child reads `/proc/<ppid>/environ` (control: it does, showing the test image's environment) and,
  after `disable_dumping()`, gets nothing.
- Compose sets `AUDIO_SERVICE_LANDLOCK: required`. On a kernel without Landlock the service stays alive (liveness ok) but
  refuses media children, fails the tasks with `INTERNAL_ERROR` (retryable) and reports **not ready** (see 7), rather than run
  FFmpeg unconfined. Measured in Compose on this host: enforced and scoped, ready.
- Measured on this kernel: ABI 8; confined child denied signalling the parent and the abstract socket (each with an
  unconfined control that succeeds).

## 4. Cover-art decoders: the exposure is real and cannot be removed

Investigation (FFmpeg 7.1.5, container):

| Probe | Result |
| --- | --- |
| ffprobe on a tagged MP3 (APIC JPEG) and M4A (`covr` PNG) with a whitelist **without** `mjpeg`/`png` | exit 1, "Codec (mjpeg) not on whitelist": `avformat_find_stream_info` opens the picture's decoder |
| ffprobe `-v debug` on the tagged MP3 | the mjpeg decoder logs JPEG marker parsing (`marker=d8`, `qscale[0]`): the cover image is parsed |
| `-allowed_media_types audio` | no effect (HTTP-protocol option in 7.1.5, as VERIFICATION_WS3 already recorded) |
| ffprobe `-nofind_stream_info` | no decoder is opened, but MP3 and FLAC lose sample rate and channels (0), every stream loses `sample_fmt` and the format loses duration and start time: the probe cannot work without it |
| ffmpeg decode passes without `mjpeg`/`png` | exit 0 ("not on whitelist" logged, non-fatal) |

Outcome: **not removable for ffprobe**, so the whitelist keeps `mjpeg` and `png`, and the claim "never decoded (`-vn`)" is
corrected in `media_args.py` and `VERIFICATION_WS3.md` to state the exposure as a **residual risk contained by Landlock
(no files, no TCP, no signals or abstract sockets), the rlimits, `-max_alloc`, the process-group kill and the container
cgroup**. Dropping the two names for the ffmpeg passes would remove the decoders from four of the seven invocations but not
from the probe, which every file passes first, and would split the whitelist and add "not on whitelist" noise to the stderr
classes; it was not done. A decision for the reviewer if the first ffprobe run is judged separable.

Container tests (`tests/test_remediation_container.py`): 9 malformed pictures (truncated, random body, 65535 x 65535 JPEG
dimensions / 2^31 PNG dimensions with a stale CRC) in an MP3 APIC, an M4A `covr` PNG and an M4A `covr` JPEG, each probed
**and** fully preprocessed, unconfined and under Landlock: every outcome was a success (`COVER_ART <case> ...: ok`, 0.15 to
0.21 s) or a mapped code, none was `RESOURCE_EXHAUSTED`, `TIMEOUT` or `INTERNAL_ERROR`, the original's SHA-256 was unchanged
and no child or temp directory survived. Controls: ordinary tagged files are accepted (3 cases), and a test proves the
decoder-open fact above. The decoders tolerated the hostile pictures here; this is evidence for the bounded outcome, not a
proof that the decoders are free of defects.

## 5. Request body cap

`_BodyLimit` (pure ASGI, innermost) counts the bytes actually received and, past `AUDIO_SERVICE_MAX_REQUEST_BYTES`, stops
feeding the handler and replaces whatever it answers with a 413 problem document. The `Content-Length` check stays in the
outer middleware, after authorisation, so unauthorised requests are refused before any body byte is read. Tests: a chunked
200 KiB body (no `Content-Length`) is a 413 with a request id; a small chunked body is served; an unauthorised chunked body
is a 401.

## 6. rmtree TOCTOU

All recursive deletes in `storage.py` are `shutil.rmtree(<bare name>, dir_fd=<parent descriptor>)`: the stale-temp removal
in `begin_output`, the session's `close`, and `cleanup_stale_temp`, which now walks `derived/` level by level with
`O_NOFOLLOW` descriptors instead of joined paths (`delete_prefix` already did this). Tests: a symlink is swapped into an
intermediate component after the directory was opened, once for `begin_output` and once before `close`; the victim
directory's file survives and the real temp directory is removed; a spy proves every `rmtree` call carries a `dir_fd` and a
bare name; a symlinked level is not followed by the stale cleanup.

## 7. `/health/ready`

Reports `503` with `{"status": "down", ...}` (the existing `ProbeResponse` shape; reason codes are logged, never paths) when
`derived/` under the storage root is missing, not a real directory or not writable (`os.access`), when no storage root is
configured, when FFmpeg is absent from the measured capabilities, or when Landlock is `required` and not enforced. Liveness
is unchanged. Existing tests changed because readiness now reports real dependencies: `test_liveness_and_readiness` uses a
fixture with a writable `derived/` and a patched FFmpeg probe (the host running the unit tests has no FFmpeg), and
`test_correct_token_is_accepted` asserts on `/v1/capabilities` plus "not 401" for readiness.

## 8. `level-series.json`

A code comment at `LEVEL_SERIES_NAME` and in `level_series_chunks`, the Pydantic `LevelSeries` docstring and the zod
`AudioLevelSeries` doc state that it is a measurement series, not waveform peaks, and must not be served as peaks until
OD-39 is decided.
