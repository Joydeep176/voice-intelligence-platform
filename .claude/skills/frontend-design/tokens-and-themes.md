# Tokens and themes

## Source of tokens
- Use the CSS variables generated by the shadcn CLI (Tailwind v4 `@theme inline` mapping of `--background`, `--foreground`, `--primary`, `--muted`, `--destructive`, etc.). **Keep the generated dark-mode variant as-is.** Tailwind's docs and shadcn's output use different `@custom-variant dark` selectors; do not hand-write a competing one.
- Components use semantic utilities (`bg-background`, `text-muted-foreground`), never raw hex/rgb values or one-off colours.

## App-specific semantic tokens
Define these as CSS variables with light and dark values, mapped in `@theme inline` like shadcn's:
- Provenance: `--provenance-recorded`, `--provenance-external`, `--provenance-inferred`
- Verdicts: one token per verdict value (taxonomy OD-30 is still Proposed; keep the tokens data-driven)
- Audio diagnostic severity and transcription uncertainty, as **separate** token families
- Speaker palette: an ordered set of distinguishable colours, assigned by machine `speaker_key` (stable across views), never by display name

Every colour pair meets WCAG AA contrast in both themes. Colour is never the only signal (see `accessibility.md`).

## Typography
- One UI sans family and one monospace family. Font choice is OD-38 (Open): until approved, use a system font stack.
- Hindi/Devanagari must render correctly: the stack must include a Devanagari-capable face. Never force Latin-only fonts on transcript or report text. Test mixed-script (Hinglish) lines for line height and clipping.
- Timestamps, durations and counts use tabular numerals (`tabular-nums`).
- A type scale defined once (Tailwind theme) and used consistently: page title, section title, body, caption, mono.

## Themes
- Light and dark are both first-class. Default to the OS preference and persist an explicit user choice (wrap storage access in try/catch). Apply the theme class before first paint to avoid a flash.
- Charts, waveform, timeline and 3D read colours from the same tokens, so theme switches apply everywhere.
